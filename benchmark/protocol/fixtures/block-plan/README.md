# Canonical block-plan semantic fixtures

The production validator applies the block-plan schema and then the cases in `semantic-cases.json`. A valid plan has exactly four cells for one replicate and one frozen subject pair crossed with both arms. It also proves that `launchOrder` is a permutation of the four cell `runId` values, each cell replicate equals the plan replicate, each prepared manifest belongs to its cell, source revision fields agree, and every path is canonical repository-relative POSIX form with nonempty ASCII segments and no `.` or `..` segment. Restricting path identity to ASCII deliberately rejects both precomposed and decomposed Unicode aliases. The exact closed plan bytes are hashed externally; a `planSha256` member is rejected as a self-hash.

The retained quota attestation exposes only typed primary, secondary, individual, and spend-control result classes plus the exact tracked policy identity and attestation identity. `policySha256` is the pinned raw-byte digest of `quota-policy.json`. `attestationSha256` is SHA-256 over the RFC 8785 canonical JSON encoding of only the policy's ordered `projectionFields`; its algorithm ID is `sha256-rfc8785-sanitized-quota-attestation-v1`. Exact native telemetry and every derived account fingerprint are private ephemeral control-plane data, excluded from the preimage and promotion and destroyed after attestation. Schema `additionalProperties: false` and semantic fixtures reject arbitrary policy hashes, unknown algorithms, and raw-derived attestations.
