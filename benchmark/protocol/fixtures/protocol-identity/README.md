# Protocol identity fixtures

These fixtures keep tracked protocol policy separate from runtime source and review identity. A tracked protocol document cannot contain its final merged commit, a review created after that commit, or the digest of the byte tree containing that digest. Those tracked fields remain null templates. After merge, the runtime plan records the reviewed PR head, final COMMENT review payload fields, exact review-body digest and marker-check result, merge commit, exact matching Git tree identities, and the independently sealed protocol raw-tree digest.

The production protocol validator proves the retained object's exact structure and cross-field equality. The CLI separately owns GitHub REST retrieval, direct marker search in the decoded body string, exact no-normalization UTF-8 body hashing, and remote Git ancestry/tree verification; the fixture does not impersonate those external proofs.

The negative cases reject legacy self-referential fields, population of tracked final-source or final-review templates, mismatched runtime merge identities, review-payload commit drift, non-owner provenance, absent marker evidence, malformed body or time provenance, missing pull-request merge time, a review submitted after merge, a reviewed/merged tree mismatch, a non-COMMENTED final review, and raw-tree mutation after sealing. The equality boundary proves a review submitted exactly at `merged_at` remains admissible.
